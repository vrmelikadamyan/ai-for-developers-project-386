# Domain docs

The frontend, backend, and API spec share the booking vocabulary in the root `GLOSSARY.md`. Architecture decision records live in `docs/adr/`.

Before exploring an area, read the glossary and any ADRs that cover it. If these files are absent, proceed silently. The `domain-modeling` skill creates them as terms or decisions are settled. The user scenario and booking rules live in `README.md`.

Use the glossary's terms in issues, proposals, hypotheses, and test names. If a term is missing, check the project's existing language and raise a real vocabulary gap during domain modeling.

If a proposal conflicts with an ADR, identify the decision and explain why it should be reconsidered.
