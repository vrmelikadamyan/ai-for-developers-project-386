# Календарь звонков

Разработайте совместно с ИИ сервис для бронирования календаря

Учебный проект Хекслета: https://ru.hexlet.io/programs/ai-for-developers
Как это должно работать: https://files.hexlet.app/a/2ipc5m

## Сценарий

Владелец календаря один и задан заранее, гость приходит без регистрации. Авторизации и внешних календарей нет.

**Владелец: создание типа встречи**

1. Владелец открывает раздел типов встреч и нажимает «Создать».
2. Заполняет название («Знакомство»), описание («Короткий созвон, чтобы познакомиться») и длительность (30 мин) и сохраняет.
3. Тип встречи появляется в списке и становится доступен гостям.

**Гость: запись на звонок**

4. Гость открывает главную страницу и нажимает «Записаться».
5. Выбирает тип встречи «Знакомство».
6. Видит календарь на ближайшие 14 дней. У каждого дня показано число свободных слотов, дни вне окна записи недоступны.
7. Выбирает дату, например субботу, 28 марта. Справа появляется список слотов по 30 минут (09:00–09:30, 09:30–10:00, …) со статусом «Свободно» или «Занято».
8. Выбирает свободный слот 09:00–09:30 и нажимает «Продолжить».
9. На шаге «Подтверждение записи» вводит имя и email и нажимает «Подтвердить запись».
10. Видит сообщение «Бронь подтверждена. До встречи!» с кнопкой «Забронировать ещё». Слот 09:00–09:30 теперь показан как «Занято» для всех типов встреч, а счётчик свободных слотов уменьшается на 1.

**Владелец: просмотр записей**

11. Владелец открывает «Предстоящие события» и видит новую запись: имя и email гостя, тип встречи, дату и время слота, дату создания. В список попадают предстоящие встречи всех типов, отсортированные по времени.

**Правила бронирования**

- Длительность слота равна длительности типа встречи. Шаг стартов, часы работы и часовой пояс фиксируются в спецификации.
- Одно время нельзя занять дважды, даже разными типами встреч, включая частичное пересечение. Встреча может начаться ровно в момент окончания предыдущей.
- Если два гостя одновременно бронируют один слот, успешной будет только одна запись, второй получит ошибку «слот занят».

## Стек

- **API-контракт:** [TypeSpec](https://typespec.io/) → OpenAPI 3 (`openapi/openapi.yaml`)
- **Бекенд:** Java 25, Spring Boot 4, Maven; серверные интерфейсы и DTO генерирует `openapi-generator`
- **Фронтенд:** TypeScript, React, Vite, Mantine; клиентский SDK генерирует `@hey-api/openapi-ts`
- **Тесты:** JUnit 5 (бекенд), Vitest + Testing Library (фронтенд)
- **Линтеры:** Error Prone + NullAway, Spotless (google-java-format), Oxlint + oxfmt, `tsc`, jactionlint
- **Окружение:** [mise](https://mise.jdx.dev/) (версии инструментов, задачи, daemons), [hk](https://hk.jdx.dev/) (git-хуки)

## Установка

Нужен только [mise](https://mise.jdx.dev/getting-started.html), остальные инструменты и их версии он возьмёт из `mise.toml`.

```bash
git clone https://github.com/vrmelikadamyan/ai-for-developers-project-386.git
cd ai-for-developers-project-386
mise trust
mise install
mise run install
```

`mise run install` ставит npm-зависимости и git-хуки (`hk install`).

## Использование

```bash
mise run dev
```

Запускает бекенд (http://localhost:8080) и фронтенд (http://localhost:5173) фоновыми процессами. Остановить: `mise daemons stop backend frontend`.

```bash
mise run check
```

Прогоняет все проверки — линтеры, проверку типов и тесты. Та же команда запускается в GitHub Actions на каждый push.

Остальные задачи: `mise tasks`.
